# SPEC-002 项目助手实施规格

日期：2026-10-16。产品范围、模型和运行时职责已由用户确认；本文的数据契约与阶段划分为据此收敛的工程设计。当前已实现 Python/OpenCode、Java 本地网关、助手页面及 80 项内容/导航目录，进入集中验收；网页检索已通过真实模型/H5 联调，微信开发者工具扫码后的交互验收待完成。

## 1. 目标与边界

从首页搜索进入独立助手页，帮助用户查找、理解内容并使用项目里全部已经完成且经过核验的功能。首页搜索只是第一个入口；后续其他入口复用同一助手及会话，不按对话次数解锁能力。

- 主模型：`opencode/deepseek-v4.1-flash-free`，通过官方 OpenCode 运行时调用。未授权付费；免费策略变化不自动换付费模型。
- 前端统一请求 Java，Java 转发 Python；Python 位于 `Dream-Back-To-Song_backend/agent/`，独立启动。
- OpenCode 承担模型与工具循环；Python 负责 API、业务工具、动作分发与回执。此决策替代早期 LangChain 循环方案，第一版不叠加 Deep Agents。
- 明确表达动作、对象与必要参数可确定时直接执行。含糊则持续有针对性地追问；建议、假设和询问后果不视为执行授权。不增加统一二次确认。
- 离开再打开可续聊；首版保存本机历史和服务端会话对应关系，不要求跨设备同步。
- 允许联网查证后回答项目未覆盖的问题，引用真实来源；外部资料不变成虚构的项目卡片或可用功能。
- 未完成的功能不接入。按具体闭环核验，不因一个板块有占位按钮就排除整个板块，也不因页面存在就宣称完成。
- 本轮产品验收环境为本地 H5 与微信开发者工具；公开部署、微信真机和真实账号同步另行验收。

术语见根目录 [CONTEXT](../../CONTEXT.md)。架构决策见 [ADR-0001](../adr/0001-agent-through-java.md)、[ADR-0002](../adr/0002-opencode-harness.md)。访谈与候选方案归档在 [调研记录](../research/002-agent-discovery.md)，不再作为并行实施规格。

## 2. 架构与职责

```text
H5 / 微信助手页 → Java /api/agent → Python 网关 → OpenCode Server → Zen 模型
                                    ↑               │
                                    └─ Python MCP ←─┘
                                       ├─ 已收录内容、已开放能力、网页检索
                                       ├─ 现有 Java 业务接口（实际接入后）
                                       └─ 客户端动作 → 前端原有函数 → 实际回执
```

| 执行端 | 职责 |
| --- | --- |
| 前端 | 首页提交、会话展示、本地历史、原有页面跳转与本地业务函数、动作回执 |
| Java | 对外 API 与统一响应、请求关联、转发 Python；已有 Java 业务继续由 Java 执行 |
| Python | 会话映射、内容目录、业务工具、动作与回执、权限拒绝、回合预算及取消 |
| OpenCode | 模型请求、多轮上下文、MCP 调用及原生模型循环；持久化使用独立运行目录 |

第一版采用异步回合加短轮询，统一适配 H5/微信，先不增加双端流式解析。Java 请求快速返回任务 ID，不用一个长 HTTP 请求覆盖整个模型及客户端操作。Python 使用 SQLite 保存会话映射、回合与动作回执；设备存储保存当前会话标识和展示历史。服务端重启、断网或页面重开后对账，不能重放已成功动作。

### 2.1 运行时边界

OpenCode 只监听 `127.0.0.1`；Python 与 Java 分别只暴露必要的项目接口。禁止把整个 OpenCode API 反向代理到前端，它还包含 shell、文件、配置和认证管理能力。

原生权限设为 `ask`，只精确允许已注册的业务 MCP 工具。Python 自动拒绝其余权限请求，包括读写文件、shell、外部目录、子任务等；不能把模型提出的权限请求转成用户授权。拒绝器未就绪时不接受产品回合，执行中失联则取消回合。针对每类原生工具补负向验收，不能只靠系统提示词限制。

使用独立工作目录及 `XDG_CONFIG_HOME`、`XDG_DATA_HOME`、`XDG_CACHE_HOME`、`XDG_STATE_HOME`；禁用项目配置、外部技能、Claude 配置和默认插件，并使用已验证的 `--pure`。`OPENCODE_CONFIG_DIR` 单独设置不是完整隔离，真实主目录 `.opencode` 仍需排查。模型进程不继承业务密钥；本地验证应明确配置来源，后续公开部署使用独立系统用户或容器。当前未完成生产隔离验收。

当前工作目录固定在系统临时目录下的项目专属子目录，避免扫描项目的 AGENTS.md；持久化和日志位于被 Git 忽略的 `agent/.runtime/`。OpenCode `/path` 已核对目录及配置来源。共享 stdio MCP 在本地串行处理回合，Python 在执行入口绑定唯一活动回合，模型不能通过更换 `turnId` 访问其他活动或排队回合。排队也计入 120 秒预算；多用户部署前需独立传输及实际身份归属校验。

权限拒绝器使用 `/event` 中的 `permission.asked`，通过原始请求 ID 回绝，并记录审计结果。1.19 的 `/permission` 曾因 grep 元数据的未定义字段返回 400，因此不再将轮询列表用作权限来源。事件连接中断即降低就绪状态并改变连接代次，执行中的回合据此停止；即使迅速重连也不能漏过该中断。

原生 `question` 使用独立的 `question.asked` 通道，没有经过权限事件；拒绝器也通过 `/question/{requestID}/reject` 自动结束此类请求，避免产品回合等待未接入的原生弹窗。产品追问以普通文本结束回合。

首个验收版本固定为 OpenCode `1.19.0`。根据运行实例的 `/doc` 核对 HTTP 契约，不盲用其他版本 SDK。本次实际结构化结果字段为 `info.structured`。

## 4. 会话、工具与动作契约

### 4.1 API 与展示数据

所有前端接口位于 Java `/api/agent`，沿用现有 `{code,message,data}` 响应。下表接口已实现，Java 仅在 `agent-local` profile 中注册，并绑定本机地址；全链路行为继续按第 7 节验收。

| 接口 | 输入/输出要点 |
| --- | --- |
| `POST /sessions` | 创建会话，返回 `sessionId`；设备保存标识用于重开 |
| `GET /sessions/{id}` | 当前消息、回合和已完成/待执行动作；重开对账 |
| `POST /sessions/{id}/turns` | `requestId,text,entry,clientState`；返回 `turnId`，相同请求 ID 不创建第二轮 |
| `GET /sessions/{id}/turns/{turnId}` | `status,blocks,actions,error`；只返回本会话的内容 |
| `POST /sessions/{id}/actions/{actionId}/receipt` | 客户端实际结果；绑定动作和回合，重复回执返回原结果 |
| `POST /sessions/{id}/turns/{turnId}/cancel` | 停止模型回合及尚未执行的动作；已经成功的动作保留 |

`entry` 仅包含入口标识和可选内容 ID，用于补充上下文，不代表执行授权。`clientState` 只发送当前任务必要的真实状态，不上传整个本地存储。会话 ID 不能充当公开部署的身份认证；当前登录为模拟，本轮只在本地可信环境联调，公开部署前补实际归属校验。

回合状态使用 `running | waiting_client | completed | failed | cancelled`。追问以正常文本展示并结束本回合，用户答复开启下一回合。展示块采用少量明确类型：`text`、`cards`、`sources`、`action_result`；卡片引用目录 ID，来源引用实际检索结果 ID，工具参数和原始日志不直接展示。

### 4.2 业务工具

工具通过 Python MCP 暴露，参数使用 JSON Schema，工具执行和结果由 OpenCode 读取。首版只保留真实需要的能力：

| 工具 | 职责 |
| --- | --- |
| `search_content` / `get_content` | 查询目录、读取真实内容，返回稳定 ID 与依据 |
| `present_content` | 把已选定的真实内容 ID 转成展示卡片；不执行业务动作 |
| `prepare_client_action` | 仅混合联网与操作的任务使用：在读取网页前固定最初用户授权的目标、能力与参数；网页出现后禁止新增计划 |
| `get_capabilities` | 返回当前已开放能力及所需参数，不返回占位能力 |
| `get_client_state` | 请求设备读取当前目标的真实业务状态 |
| `execute_client_action` | 分发一个已开放动作并等待真实回执，返回成功/失败/取消/待核对 |
| `search_web` / `read_webpage` | Exa 官方免 Key 检索与公开文本网页取证；保存真实来源 |

这些是业务入口，不是给模型任意调用 Java URL、执行 JS/Python 或数据库 SQL 的通用工具。未知对象、未开放能力、参数不匹配均返回可纠正的业务错误，不偷偷改成其他动作。卡片通过 `present_content` 的 JSON Schema 参数生成；正文使用 OpenCode 普通文本返回。正式工具循环中曾观察到 JSON Schema 输出格式持久化后 `/message` 返回 `Expected OutputFormatJsonSchema`，该回合最终超时；当前不依赖此组合，也不解析模型正文里的 JSON 来拼卡片。早期无工具追问的结构化样例仍只证明该样例。

### 4.3 客户端动作与回执

```json
{
  "actionId": "由服务端创建的唯一标识",
  "turnId": "所属回合",
  "capability": "food.next",
  "targetId": "food:suzhengqiezi",
  "args": {},
  "expectedState": {"stepIndex": 0, "completed": false}
}
```

前端只把白名单动作映射到现有函数；修改业务数据前核对当前状态与 `expectedState`。有变化就回报 `state_changed` 并读取新状态，不在旧上下文上继续推进。只读页面导航、图片预览和视频打开不以业务状态作为前提，不上传无关本机内容；仍限制目录目标并记录回执。菜品步骤取自真实内容，末步完成继续沿用现有业务规则。

回执包括 `actionId,status,resultingState,error`，`status` 为 `succeeded | failed | cancelled | state_changed`。未收到回执只能表示结果未知，不能说“已完成”。成功后才能写 `action_result` 并推进模型对话；失败必须给工具真实原因。

同一 `actionId` 在设备持久化执行结果，重发时返回原结果，不再执行“下一步/新增”。应用在业务写入与回执记账之间崩溃时，先用预期状态和实际状态对账，不能因查不到回执就再推进一步。重开、轮询重试和 Java 超时都不生成新的动作 ID 来重做原动作。避免承诺跨本地存储的 exactly-once。

首页每次用户提交生成独立 `requestId` 并放入入口参数；同一 URL 刷新、重开或本机确认丢失时复用该 ID，先核对服务端历史后再决定是否提交。不能仅以页面 `onLoad` 再次发生就重新执行入口里的动作。

同一回合重复的能力、目标、参数复用原动作 ID，不能靠重新读取进度再生成一次“下一步”。若业务写入及结果读取已成功，但最终回执记账失败，返回核对过的实际结果并保留内部错误及执行前记录；不能谎称业务未发生。旧制作页面只对明确收录的路由同步进度，其他页面不写制作存储。

## 5. 模型失败、取消与联网

沿用成熟 Agent 的分类恢复思路：暂时性网络错误、429 或 5xx 可在同一回合有限恢复；认证/免费策略 403、非法参数及明确业务拒绝立即报告。OpenCode 管模型层恢复，Python 管回合总时限和取消，Java 不重放整轮 POST。实测内置恢复行为后再确定是否需要额外恢复，不能无意叠加 SDK/框架多层重试。

初始工程预算为每轮最多 120 秒、最多 8 次业务工具调用；客户端动作等待同样计入总时限。预算需要在执行点生效，不能只写在提示词里。用户停止、预算耗尽、权限拒绝或服务中断都保留历史及已成功动作。失败与“没有相关内容”分开，不默认把一次模型失败伪装成普通关键词检索成功。

网页检索与读取由项目自己的 Python 工具提供。检索调用 Exa 官方托管 MCP `https://mcp.exa.ai/mcp` 的 `web_search_exa`，官方支持匿名、免 Key、免费限流使用；不调用需认证的 Agent 服务，也不配置付费回退。已用项目自身 User-Agent 实测真实检索，并通过真实模型/H5 返回故宫来源。429 明确提示免费检索限流，失败不伪装成空结果。公开 URL 读取另行实测了故宫《千里江山图》页面；读取网址与搜索分开验收。

网页结果保存标题、URL、实际证据、检索时间和引用 ID。回答来源必须对应真实结果；没有可靠依据则说明无法确认。只发送必要的公开查询词，不发送整段私有对话或业务状态；公开网页读取需要拒绝本机和内网目标及其重定向。网页文字属于证据，不得授权执行动作、改变规则或调用系统工具。

读取时固定连接已核验的公网 IP，TLS 仍校验原主机名，每次重定向重新检查。本机隧道实测返回 `198.18/15` Fake-IP，针对该情形使用 Google HTTPS DNS 获取真实公网地址后固定连接；保留地址字面量、私网和混合 DNS 仍拒绝。引用区分项目参考资料与实际网页证据，重复 URL 保持同一来源 ID，不能用项目引用覆盖真实抓取的证据。联网后仅能执行联网前固定的动作计划，改参数、改目标或新增操作均在工具执行点拒绝。
