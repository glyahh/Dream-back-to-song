## 架构审查

本期依赖方向为：分类/详情/制作页面 → 纯内容表；菜品详情与制作页面 → 独立进度工具 → uni 本地存储。画作不读写菜品进度。三个新页面通过 scoped 样式复用 src/styles/experience.css，未引入状态库、CMS、图片预览库、后端接口或数据库修改。

12 个菜品共用详情与制作页面，4 幅画共用详情页面，避免逐条复制页面。内容使用稳定 key，分类局部 id 不作为跨分类存储标识。现有结构足以承载当前范围，无需追加架构层或迁移业务模块。

前后端仍为独立仓库。前端登录为模拟实现（src/utils/auth.js），本轮静态内容和本地进度验收不代表前后端业务联调完成。

以下是历史问题，未将其混入本期接口改动：

| 等级 | 位置 | 发现及处理 |
| --- | --- | --- |
| P2 | backend 的 OrderController.java:41、44、116 | 请求体没有 @Valid，直接对 items 调用 stream；缺失列表会进入内部错误处理，而不是预期参数错误。后续订单模块应补齐请求校验和错误请求测试 |

| 后续排期 | [已有问题](../已知问题.md) | 旧菜品制作断点、服饰失效跳转、旧详情返回按钮遮挡继续保留，不算作本期修复完成 |
