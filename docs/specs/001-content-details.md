## 1. 目标、范围与边界

补齐 12 个菜品、4 个名画内容条目，使现有分类入口能够进入真实详情；12 个菜品同时具备完整的分步制作引导。沿用现有宋风配色和简洁文案，不改其他业务模块。

整体排期保持：本 SPEC 第一；首页智能搜索第二；原有五个菜品的制作断点和服饰跳转第三。关注、购物车、换装效果、课程收藏、出行体验、支付及其他未完成功能不纳入本 SPEC。

## 2. 用户已经确认的规则

- 菜品详情包含独立成品图、简短介绍、材料、做法概览及制作入口。
- 每道菜提供一套完整的步骤引导，支持上一步、下一步、完成；不增加拖拽、模拟食材操作或烹饪计时。
- 12 张成品图采用统一风格的 AI 示意图；步骤以文字为主，不要求逐步专图。
- 成品图以现有图片为视觉参照，采用宋式器皿、低饱和灰绿与米黄色、古朴案面和留白，呈现宋风静物画意；不使用现代商业摄影构图。
- 每道菜独立保存本地进度，离开后再次进入继续；不做账号和服务器同步。
- 完成状态保留。完成页提供“返回详情”和“重新制作”，只有主动重新制作才重置当前菜品，不影响其他菜品。
- 酒采用温酒示例；汤、露分别采用一种明确的日常饮品示例，详情说明示例名称，不新增酿造系统。
- 名画提供可确认的作品信息、简短画面与建筑看点、点击查看可缩放大图。不增加收藏、分享和局部热点。
- 暂不把微信真机验收作为本期开发前置条件。
- 按用户补充要求，新增界面的风格与布局先参照已开发页面：圆形菜图、竖排木牌、浅绿标题栏、隶书/楷体、米白金边内容框与现有图片按钮。界面不展示 AI 生成、衍生或成品示意等素材说明；生成来源仍记录在开发资料中。

## 3. 实现约定

### 内容与素材

- 以现有分类中的条目为准，每道菜一套材料与完整做法，不按界面需要截断到“半熟”就结束。步骤数量由实际做法确定。
- 酒、汤、露保留列表原名；温酒、红枣汤饮、桂花清饮分别作为具体日常示例。汤与素汤内容区分，前者为饮品，后者为配餐素汤。
- 食谱正文给出能够实际执行的用量、操作顺序和完成判断；不添加未经支持的朝代归属、养生或治疗功效。
- 来源、核实范围及 AI 配图来源记录在开发资料中；页面只展示必要的简短说明。
- 12 张成品图风格统一、主体对应菜品、没有文字和水印，分类卡片、详情、完成页使用同一条目的图片。
- 高分辨生成原图和临时素材放在工程外的“项目资源/梦回宋朝”。压缩后的运行必需图片放入前端静态资源目录，12 张总计不超过 1 MiB；不将未压缩源图、生成中间文件放回工程。
- 当前没有可用 OSS 上传配置，本轮默认随前端打包必要图片，不以开通上传权限为前置条件；不批量运行现有 OSS 上传工具。
- 名画沿用现有配图及其比例；不生成替代画作。预览使用对应画作图，保持完整画面，不裁切后冒充全图。

### 页面与内容组织

- 用“菜品详情、制作引导、名画详情”三个共用页面展示 16 个条目，内容独立维护，不复制 16 套页面或为每个步骤新增页面。
- 新增路由为 `/pages/food/detail/content?key=...`、`/pages/food/making/guide?key=...`、`/pages/lodging/painting/detail?key=...`，注册到现有对应分包。
- 原有 93 个页面及有效路径保留；仅将本次 16 个条目的无效入口改到新路由。原有菜品的详情与制作逻辑不顺手迁移。
- 分类中现有局部数字 id 不作为跨分类标识；新内容使用上表稳定标识，展示名称和内容由内容表读取，不由 URL 中的 name 参数覆盖。
- 菜品内容包含 key、分类、名称、简介、图片、材料、步骤和来源；名画内容包含 key、名称、图片、可确认的作品信息、看点和来源。使用普通 JS 内容表，不引入 CMS、数据库、状态库或搜索接口。
- 无效 key 显示“内容不存在”和返回所属模块列表的入口，不加载其他条目冒充。

### 制作进度与完成状态

- 新增独立存储键 `food_making_progress_v1`，按菜品 key 保存 `{ stepIndex, completed }`。不读写现有订单、收藏、创作或其他制作流程的数据。
- 首次进入从第一步开始；步骤切换时保存最后查看的位置。上一步、下一步在共用页内切换，不通过不断叠加路由栈翻页。
- 已有未完成进度时，详情显示“继续制作”，进入最后查看的步骤；刷新页面或重启应用后仍可恢复。
- 点击末步“完成”后保存 completed 状态；再次从详情进入时展示完成页，不自动重新开始。完成状态仅代表用户完成了应用中的引导。
- “重新制作”只将当前菜品重置到第一步并清除其完成状态。
- 首步不提供无效的“上一步”；末步提供“完成”。返回详情保留进度；完成页不保留虚假的“保存成功”“分享成功”操作。
- 进度写入失败时明确提示未保存；损坏或越界的单条记录按该菜首次进入处理，不清空其他菜品数据，不做额外迁移框架。

### 名画预览与内容准确性

- 使用 uni-app 自带图片预览能力实现放大查看，不新增图片查看依赖。
- 千里江山图与清明上河图以故宫馆藏资料核对作者、时代；未核实的精确创作年份不填写。
- 秋窗读书图、妆靓仕女图保留当前显示名称。现配图与公开作品资料的对应关系尚有题名、传称或定年差异，无法充分核实的作者、年代、材质、尺寸不强行填写。
- 有依据的传称必须保留“传”等限定，不把相似题名或画面比对直接当成同一作品的确定鉴定。
- 名画模块与菜品进度互不关联。
